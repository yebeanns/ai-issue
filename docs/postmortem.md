## STAR

### Situation (상황)
v0.2.0 배포 다음 날, 내부 분석 대시보드에서 **모든 t-검정 결과의 p-value가 `0.000`으로 표시**되었다.
표본 수가 크고 효과 크기가 큰 A/B 테스트 3건이 "p < 0.001, 매우 유의"로 보고되었고,
그중 1건은 실제로는 유의하지 않았을 가능성이 있었다.

```
ttest_ind(group_a, group_b)  # statistic=48.2, pvalue=0.0  ← 확인 필요
```

1. 4시간 내 원인 규명 및 핫픽스 배포
2. 영향받은 리포트 범위 산정·재계산
3. 동일 유형(수치 안정성) 재발 방지책 수립

## 5 Whys

1. **왜 p-value가 0이 나왔나?** → `1 - cdf(t)`가 극단 t에서 0으로 반올림(underflow)됐다.
2. **왜 `1 - cdf`를 썼나?** → `sf`(survival function)의 존재를 구현 시점에 고려하지 않았다.
3. **왜 극단값 테스트가 없었나?** → 완료 조건(DoD)이 "SciPy와 일치"였고, 테스트 데이터가 평범한 구간에만 있었다.
4. **왜 배포 전에 못 잡았나?** → 릴리스 체크리스트에 수치 안정성 항목이 없었고, #11은 `priority: high`지만 블로커는 아니었다.
5. **왜 블로커가 아니었나?** → "버그"와 "릴리스 차단"을 연결하는 규칙이 없었다. (근본 원인)
